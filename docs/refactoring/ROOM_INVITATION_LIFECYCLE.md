# 房间组队邀请生命周期

“满员”结束一轮组队邀请。房间继续存在，房间控制面板继续服务于下一轮邀请。

## 状态与入口

`InvitationDatabaseManager` 管理现有 `teamup_invitations` 表中的 `pending`、`active`、`ended` 状态。每个语音房最多有一条活跃邀请，由数据库部分唯一索引保证。

普通组队消息和 `/invt` 共用发布流程：预留邀请 ID，发送 Bot 回复，然后在一个短事务中关联准确的消息 ID、结束上一轮邀请并激活新邀请。发送失败时保留上一轮邀请；网络结果不确定时不重复发送。恢复过程最多检查该次发送时间之后的 100 条消息，只匹配本 Bot 发出的同一邀请按钮标识。

邀请回复的动态按钮使用 `teamup:full:v1:<invitation_id>`，每次点击重新查询持久化状态。旧版 `room_full_button` 保留兼容入口，通过消息 ID 找记录；无法可靠关联的旧消息提示重新发布。

两个满员入口保留各自权限：邀请回复要求发布者本人且仍在对应语音房；房间面板要求操作者在对应语音房。权限通过后都按邀请 ID 结束，不再按点击者 ID 删除整个房间的记录。

发布、替换、结束和恢复操作在同一进程内按房间串行处理。数据库条件更新仍保证迟到的旧请求不能结束新邀请，重复结束只成功一次。数据库事务中不等待 Discord 网络请求。

## 展示与恢复

组队展示板只查询活跃邀请，不再以五分钟计时判断是否活跃。创建、结束时立即刷新，原有两分钟后台刷新负责恢复暂时失败的展示板更新。人数读取当前语音房成员数，记录时间统一使用 UTC。

结束邀请时同时保存待更新消息标记。共享的满员样式函数移除按钮，并返回更新、消息不存在、权限不足、无效消息或暂时失败的明确结果。重复更新不会重复添加满员标题。

满员前保持原始 Discord 频道链接，房间名称单独保存在邀请记录的 `voice_channel_name` 字段。满员更新优先使用当前频道对象，缓存缺失时尝试 API 查询，无法查询时使用保存的名称。频道删除事件先持久化删除时的名称，再更新消息，保证暂时编辑失败后仍可重试。兼容读取 2.0.8 消息中的名称；旧记录没有名称且频道无法找回时显示频道 ID，API 明确返回不存在时标注已删除。

每分钟恢复任务处理待更新消息、未确认的发布和离线期间删除的房间。暂时的消息更新失败最多尝试三次；权限不足、无效消息或重试耗尽后标记为 blocked 并记录日志。数据库状态已经结束但界面尚未同步时，用户收到部分完成提示。已结束且同步完成的历史记录满 14 天后清理，活跃邀请和待处理记录不受历史清理影响。

`10062` 在首次应答处记录交互年龄、应答耗时和实体信息，随后终止本次操作。不能使用已失效的请求继续结束邀请。

## 数据库迁移

迁移前备份数据库，并停用旧代码的写入者。使用 `schema_migrations` 的 `room_invitations` 命名空间执行迁移。

2.0.9 使用该命名空间的第 2 版迁移，仅新增可空的 `voice_channel_name` 列，不修改已有邀请状态或计数。升级前在加密副本验证迁移，启动时自动应用。迁移可重复执行；回退到 2.0.8 时可以保留新增列，不要用旧库覆盖新数据。

旧表中仅保留每个房间最新、尚未到期且有消息 ID 的记录为 active；其余旧记录设为 ended。有消息关联的结束记录会同步为满员。已被旧清理逻辑删除的记录无法直接恢复，也不会把所有仍显示按钮的历史消息重新激活。迁移可重复初始化而不复活已结束邀请。

旧 `expires_at` 字段保留用于兼容表结构，不再决定新邀请的生命周期。回退代码时不能直接运行旧版的到期清理器，也不能用旧数据库快照覆盖升级后新增的用户状态。

## 验证

针对性测试：

```bash
./.venv/Scripts/python.exe -m pytest -q tests/test_invitation_lifecycle.py tests/test_invitation_full_message.py tests/test_voice_channel_interaction_flow.py tests/test_create_invitation_keyword_flow.py
```

覆盖两个满员入口、非发布者房间成员、精确消息关联、新旧邀请替换、并发结束、旧请求隔离、旧记录迁移、长时有效、无原始 View 的动态路由恢复、首次应答失效、发送失败、发送结果恢复、消息重试及房间删除。

真实测试服还需分别记录：消息创建和编辑的 API 读回、真人按钮应答、等待超过十分钟、机器人重启后的按钮点击。测试夹具调用回调并不等同于真人 Discord 交互；只有客户端实际点击才能确认真实首次应答与客户端提示。
